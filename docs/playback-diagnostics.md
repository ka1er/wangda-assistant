# 播放暂停诊断

这是独立的临时测试脚本，用来定位“打开第二门课程后，第一门暂停”的触发时机。它记录事件，不解除并发限制，也不修改播放进度。诊断脚本独立版本为 `0.1.0-test.1`，网大助手版本以 README 为准。

## 安装

1. 在网大助手中暂停任务，并暂时禁用其他自动播放、自动切课脚本。
2. 篡改猴中新建脚本，粘贴 `dist/wangda-playback-diagnostics.user.js` 的全部内容并保存。名称应为“网大播放暂停诊断”。请单独安装，保留原来的网大助手及其任务数据。
3. 刷新已打开的网大课程页面。左下角应出现“播放暂停诊断”。如果没有出现，先确认这个脚本已启用且有网大访问权限。

安装后要刷新，再进行记录：脚本在页面加载前监听连接，不能补录安装前已经发生的消息。

## 一次测试

选择两门可正常播放的视频课程 A、B，先记下平台显示的各自进度。不要打开开发者工具或外部浏览器接管。

1. A 页面选“此标签页 A”，点“开始记录”，正常播放约一分钟。确认面板中的播放时间增加。
2. 保留 A，在新标签页正常打开课程 B。B 页面选择“此标签页 B”，点“开始记录”，先不要手动播放，等待约十秒。如果平台已经自动播放，就保留这个实际结果，不再强行作为“未播放”样本。
3. 需要手动播放时，在 B 点一次“标记此刻”，再正常点击播放器开始播放。等待约半分钟，观察 A 是否暂停、何时出现平台提示。
4. 切回 A，点一次“标记此刻”，等待约十秒。不要反复抢播。
5. 在 A、B 分别点“停止记录 → 导出日志”，保留两个 JSON 文件。刷新或关闭页面会丢失内存日志，先导出。
6. 导出后，再返回课程列表、刷新，记录平台实际保存的 A、B 进度。日志中的播放时间只用于对照，不等于平台认可的进度或学时。

反馈时提供两份诊断 JSON，以及“B 打开时是否自动播放、A 何时暂停、页面提示、刷新后各自进度”的简短文字。无需发送账号、完整课程地址或网络抓包文件。

## 日志含义

| 事件 | 含义 |
| --- | --- |
| `pause-call` | 页面调用了当前原生媒体的暂停方法，附允许的站点脚本文件名和行号摘要 |
| `pause` | 媒体实际触发暂停事件；浏览器或播放器内部暂停也可能只有此事件 |
| `study-notice`，1003 | 捕获到已知学习连接收到“打开新课程”通知 |
| `study-notice`，1002 | 捕获到多客户端学习通知 |
| `study-notice`，1004 | 捕获到观看人数上限通知 |
| `wrapper-close-notice` | 收到已知跨窗口关闭信号 |
| `page-notice` | 页面出现对应的已知平台提示 |
| `sample` | 当前页面原生媒体的时间、暂停状态及课节状态计数 |
| `visibility` / `manual-mark` | 标签页可见性变化 / 手动标记，用于对照操作时间 |

面板时间使用北京时间，JSON 的 `at` 使用带 `Z` 的 UTC 时间。同一电脑的两个文件可按 `at` 对照。

相近时间发生的通知和暂停能缩小调查范围，但仅靠时间接近不能证明因果关系。暂停调用栈摘要可能为空，不能据此判定没有脚本调用。

## 覆盖范围与停用

脚本只观察当前顶层页面的原生视频、音频。iframe 内播放器、页面隔离、脚本安装顺序或未知消息格式可能导致漏记。面板显示“已观察学习连接 0 个”时，不能排除服务端通知。必要时应重新安装后刷新复测，而不是根据空日志下结论。

观察器透传原有暂停调用、连接和平台消息，仍可能因站点兼容性改变表现。若安装后出现新异常，先停用诊断并刷新，恢复后再反馈现象。

日志只在当前页面内存保留，最多 600 条，超出后删除最早事件并记录裁剪数量。导出只包含固定事件、状态和允许的脚本文件位置，不保存课程名、课程 ID、媒体地址、请求地址、账号或消息正文，不上传日志。

测试结束后，在篡改猴禁用“网大播放暂停诊断”，刷新测试页面，恢复需要使用的原助手。点“停止记录”会停止写入日志；禁用并刷新才会移除本页观察器。

## 本地检查

```powershell
npm run check:diagnostics
```

检查使用模拟页面，不代表真实网大的播放和学时流程已经验证。
